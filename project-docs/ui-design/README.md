## 后续按这条流程推进

1. **选具体参考。** 每次给选择配参考图或短演示，指出借鉴部位、如何用于本项目，并给出推荐；用户可以选择局部、混合或都不喜欢。记录到参考网站与决策记录。
2. **只解决一个区域。** 当前已经启动投影局部网页，用两个既有机构验证切换，不扩展为全首页实施。
3. **提供可操作的局部对比。** 每轮最多比较两个局部方案，其他条件尽量一致；根据本轮问题提供必要的参数调节。
4. **收集并归档反馈。** 记录保留、修改、否定、未决问题及对应文件版本。由用户确认设计方向。
5. **更新基线后再扩展。** 轮播、目录、实验内容分轮打磨；正式页面实施与接入按后续明确授权进行。

当前进展：U27 已明确 V06 背景空旷单调的问题。V07 用近中远层次补充环境，不改目录或机构运动；“观看设置 → 背景对比”可比较新环境与 V06。**V06 对照不代表恢复认可，V07 的具体效果也仍待用户反馈。**

## 状态与维护规则

- 设计状态：`探索中` / `待用户确认` / `用户已确认` / `已否定` / `已替代`。
- 实现状态另记：`未实施` / `局部样稿已制作` / `正式实现完成` / `本地检查通过` / `待用户验收` / `用户验收通过`。检查通过必须说明检查对象与范围。
- 每轮记录：目标 → 参考依据 → 样稿版本 → 修改内容 → 用户反馈 → 当前结论 → 验证情况 → 下一步。
- 新决定追加到决策记录；旧决定标明被谁替代，不悄悄改写历史。README 和设计共识只展示当前有效状态，并链接原记录。
- 用户明确话语是确认依据；助手推荐、生成成功、切换样稿或点击控件均不代表认可。
- 已归档历史样稿保留原样，后续修改保存为新版本。截图、视频按来源和状态归档，不把加载页当作有效设计参考。
- 本工作区保留在 `project-docs/`，不写入 `meshlab/dist/`。现有 Pages 工作流发布的是 `meshlab/dist/`；本次没有修改工作流、同步或部署。

涉及真正的机械三维实现时，继续遵守已归档的 [GL16 视觉基准](https://github.com/Slack-ZH/meshlab/blob/5239f10876ca0bab3c7a3168d8d2fa1dc782804e/project-docs/视觉基准.md) 和 [机构交付标准](https://github.com/Slack-ZH/meshlab/blob/5239f10876ca0bab3c7a3168d8d2fa1dc782804e/project-docs/机构交付标准.md)。这两个链接指向已有备份提交，不将其他机构工作重复纳入本次 UI 上传。首页视觉讨论不自动扩展机构数量或改变原有负责人分工。
