# 机构交付标准

2026-11-17 起用于新增、批量制作和补齐机械教学实验。依据用户明确指定的“摩擦轮传动 + 齿轮齿条传动”完整功能标准，以及 [GL16 视觉基准](视觉基准.md)。

这份标准约束交付完整度；各机构的运动学、零件数量、尺寸和教学目标仍按自身结构实现。不能把“页面存在、三维能显示、模型会动”当作完整交付。

## 范围与模板

开始每批工作时，写明授权清单、数量、负责人和对应教学目标。用户已经明确的 W 范围继续有效；他人的“在做”项目不自动属于本轮。只修改授权机构及其必要公共接入，保留已有工作区改动。公共模块改动必须检查原有模型的兼容性。

统一入口是 `meshlab/dist/experiments/`：

- `app.mjs`、`style.css`：完整页面交互及响应式布局。
- `catalog.mjs`：参数、读数、零件规格和逐机构拆装讲解。
- `chat-context.mjs`：提问快照、有效/无效参数、重试与兼容请求。
- `scripts/build-experiments.mjs`：从基准提取公共页面部件并生成实验入口；先校验整批，再写文件。

保留 `apple.css`、`apple.js`、`chat.css`、`chat.js` 的公共能力。旧 `linkages/app.mjs`、`mechanisms/app.mjs` 是历史简化界面，不用于新页面。只改变 HTML 外观或添加隐藏占位控件不算补齐功能。若机构确需新交互，扩展公共实现并补相应检查。

## 每个机构的完成清单

| 项目 | 必须达到的结果 | 如何检查 |
| --- | --- | --- |
| 教学任务与运动 | 输入、输出、单位、约束、边界和教学简化清楚；模型、公式、曲线相符 | 独立已知结果/极限工况测试，加真实页面操作 |
| GL16 外观 | 共享材质、灯光、地面、选中高亮与透明支承；取景适配装配关系 | 桌面及手机默认、选中、拆装截图 |
| 完整公共界面 | 导航、目录、搜索、分类、AI/解读切换、透明度开关都可用 | 静态完整性与浏览器操作 |
| 零件解读 | 每个实际部件都有名称、作用、规格、外观说明；点选高亮及可选标注一致 | 遍历实际零件，不只检查输入件 |
| 参数 | 数值框与配套滑块即时更新模型、规格、读数和曲线；不能另加“应用参数”步骤 | 两种输入都操作；校验边界、无效输入和恢复 |
| 无效输入 | 暂停计算及导出，保留上一有效模型并明确提示；AI 不混淆两组状态 | 无效参数、停机、恢复及对应聊天快照 |
| 运动与视角 | 播放暂停、速度、输入定位、复原、视角、全屏正常；拖动功能确实命中可见输入件 | 实际指针操作与边界检查；按下鼠标不跳角 |
| 慢放约定 | 1× 为工况的 20%；动画倍速不改变工况读数 | 数值测试及页面说明 |
| 拆装 | 对应实际装配关系的分步标题、说明、部件映射；展开/复原保持输入位置 | 遍历所有步骤及实际组件；手机按钮和说明不被遮挡 |
| 朗读 | 中文说明、规格及停止/切换状态正确 | 调用测试；设备实际发声单独记录 |
| AI | 登录入口、正确机构快照、选中件、参数、结果、拆装状态；重试保留原快照，追问取新快照 | 模拟流式请求、错误/重试/停止/新对话；真实服务另列证据 |
| 原理与资料 | 原理页有本机构内容和当前工况；JSON、带单位 CSV 与当前有效参数一致 | 下载后读取核对，不能只看按钮存在 |
| 手机流程 | 模型后紧接测量与参数，再到助手；无横向溢出、模型裁切或控件遮挡 | 390×844、360×740；桌面 1440×1080 |
| 原有页面兼容 | 必要的公共改动保留其他模型原协议与页面功能 | 兼容检查、开工前后文件对照 |

## 批量执行顺序

1. 读取本标准与视觉基准，列清本批机构及验收动作。
2. 先完成一个机构的纵向流程：模型 → 参数 → 规格与拆装 → AI → 桌面/手机 → 导出。自检跑通后再扩展同一模板，无须因此额外要求用户逐个批准。
3. 为每个机构实现有明确预期结果的专属行为测试。注册到 `scripts/experiment-teaching-checks.mjs`；新增机构未注册时，生成和静态检查会报错。数值模型还须有对应运动约束测试。
4. 运行完整性、计算/上下文和浏览器检查。修复问题后复测受影响项目；公共改动检查原有实验。
5. 提交本地逐项记录：每个机构的检查结果、对应证据、未实测项和可打开入口。只记录实测结果，不用“文件齐了”代替检查。

## 本地检查命令

在 `meshlab/` 目录执行：

```text
npm run check:experiments
npm run test:experiments
```

第一条只读检查全部已注册页面：必需功能、配套参数控件、专属内容及测试、实际页面与统一模板是否一致。第二条运行防遗漏测试及运动/上下文测试。需要生成页面时执行 `npm run build:experiments`；范围较小时使用已有五项/六项构建入口或 `buildPages(names)` 的明确名单。

完整浏览器检查前，启动本地预览与专用浏览器，设置 `MESHLAB_BASE_URL`、`MESHLAB_CDP_URL`，然后执行：

```text
npm run verify:experiments
```

该命令依次运行静态检查、单元检查、完整页面、模拟 AI、直接拖动/手机拆装及原有模型兼容检查，任一失败会停止。浏览器使用独立配置，各组串行执行，避免后台节流影响动画/滑块检查。此命令不启动服务、不登录用户账号、不同步或部署。

自动检查的边界：静态检查能发现缺控件、缺公共模块、参数滑块不匹配、模板漂移、拆装内容缺失和新增机构没有专属测试；它不能证明三维正确、按钮真能操作或 AI 回答质量。截图审查、运动约束检查、浏览器检查仍然必需。

## 状态与证据

- **实现完成**：功能及专属内容齐备，不等于检查通过。
- **本地检查通过，待用户验收**：按机构列出已运行且通过的检查；同时清楚写明未实测或受环境阻碍的项目。
- **用户验收通过**：只能依据用户明确验收结论更新。

“AI 接口健康”“模拟聊天通过”“真实账号收到回答”“回答符合当前机构”是不同证据，分别记录。语音 API 调用成功不等于已听到声音。缺依赖或其他原因未运行的测试不得计为通过，也不得笼统声称完整测试套件已通过。

当前 11 项的已完成范例见 [2026-11-17 本地验收记录](../meshlab/docs/eleven-mechanisms-full-standard-20261117.md)。后续需重新检查当次实际代码；历史报告不能替代新改动的证据。
