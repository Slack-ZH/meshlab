## 4. 硬边界（Bounds / Anti）

### 阶段 A 允许

- 只读当前仓库中与任务相关的代码、配置、文档和已存在的测试报告；必要时只读公开官方资料。
- 使用 Git 查询、文本检索和不会落盘的纯计算；访问范围以本项目和任务相关资料为限。
- 读取公开客户端配置以分析集成，不读取或输出 `.env`、认证缓存、私钥、浏览器凭证及其他项目/用户资料。

### 阶段 A 禁止

- 所有源码、文档、锁文件、资源及 Git 引用写入，包括自动格式化、自动修复、提交和建分支。
- 安装依赖/浏览器/CLI/引擎，启动服务或浏览器，运行会生成报告或访问后端的测试脚本。
- 真实问答、注册、邮件验证、密码重置、预算变更或任何可能产生费用的调用。
- push、PR/Issue/评论、部署、公开分享、报名提交、联系官方或修改账号权限。
- 读取凭证确认登录。认证文件存在不等于可用登录；CLI 未发现不等于允许自动安装。

### 后续实施也不得走的捷径

- 不删除/放宽测试断言、不用硬编码截图或固定值冒充参数联动、不伪造服务响应冒充真实联调。明确标记的 mock 只能证明模拟路径。
- 不运行 `build_model.py`、`build_documents.py` 等全量生成命令覆盖现有工程资源，除非该资源生成本身是单独确认的目标。
- 不擅自改 Firebase 项目、Worker 绑定/数据库、费用模型、账号预算或 API 提供商；每账号限额不等于全站供应商账单硬限额。
- 不把几何尺寸变化硬接为功率变化。遵守当前首版单进单出模型与教学适用域，不宣称制造级校核。
- 不强制重置、清理、stash 或覆盖同学的未提交改动，不在生产 main 上直接修复。
- 不因只是文档变更而忽略发布影响：本仓库 push 到 main 可触发 Pages 部署。所有远端发布动作仍需明确批准。
- 不绕过 Codex 或宿主的审批/沙箱保护；遇到限制直接报告，不改用无沙箱或危险权限参数。

## 6. 优先级与取舍（Trade）

1. 参赛有效性与数据/费用安全。
2. 首页到两个实验的核心演示可走通，已有 GL16 不被破坏。
3. 教学解释、参数与数值结果一致，明确模型边界。
4. 移动端操作、必要性能与界面一致性。
5. 只有前三项不受影响且另获批准，才考虑自然语言控制、更多机型或高保真仿真等新功能。

问题等级使用 P0（阻断演示/安全费用风险）、P1（显著影响核心教学与交互）、P2（非阻断改进）。参赛规则解释单独列为待确认事项，不能通过修改代码“修复”未知资格。

## 8. 前提核验与停损（Unknown）

| 情况 | 处理 |
|---|---|
| 工作区有同学/用户改动，或任务基准已变化 | 只读记录，隔离冲突问题；相关写入前请用户确定基准，不覆盖、不自动 stash |
| 依赖/CLI/浏览器不可用 | 报告缺少项；阶段 A 继续其他独立静态检查，不下载安装 |
| 源码与旧文档不一致 | 当前源码用于描述实现，运行证据用于判断通过；先列差异，不把文档滞后自动判成产品故障 |
| 同一验收路径连续失败三次 | 停止该路径，报告命令、环境和失败点；其他独立检查可继续 |
| 原生权限或沙箱拦截 | 停止受限动作并报告，不扩大权限绕过 |
| 发现凭证或生产数据风险 | 不显示敏感值；只报告文件位置/风险性质，停止可能传播或修改数据的动作 |
| 官方资格或实际账号能力不明 | 标为待确认，不冒充合规；继续不依赖该前提的立项与评审 |
| 验证变差或范围扩张 | 停止该改动，保留差异与证据；由维护者决定修正/撤回，禁止破坏性清理 |

## 9. 红队修订落实

- **失败前提 → Proof**：旧交接不等于最新实现，先核对基线和证据；CLI/服务/测试未运行不得写可用。
- **伪完成 → Anti**：禁止改断言、伪造模型联动/问答/截图或倒写 Qoder 开发过程。
- **资源与范围 → Bounds**：首阶段只读；不重构、不换技术栈、不新装引擎、不全量生成工程资源。
- **目标冲突 → Trade**：先保资格和核心演示，后做外观与扩展。
- **未知/事故 → Unknown**：付费、发布、账号操作、基线冲突和混用规则分别设门，不拖住独立评审。
